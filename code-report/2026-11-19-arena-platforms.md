# 배틀 화면을 PokéRogue 원본 구도로 (2026-11-19)

## 결정

- 앱이 직접 그리던 갈색 타원 지면(`BattleGroundSurface`)을 없애고 원본 발판 레이어를 쓴다.
- 사용자가 "윈도우와 동일"을 골랐다. 윈도우 `bd32856` 과 같은 규칙을 Mac 에 옮겼다.
  - 원본 필드(320×132)를 전장 높이에 맞춰 확대하고 가운데 정렬한다. 좌우는 잘린다.
  - 발판과 포켓몬을 원본 좌표에 둔다. 아군 발(y 148)은 필드 아래(132)라서 원본처럼 16칸이 가려진다.
  - 포켓몬은 아틀라스 1픽셀 = 필드 1칸이다. 싱글 351/132(2.66배), 더블 299/132(2.27배).
- 소품(`_b_1~3`)은 넣지 않는다. 사파리는 레이아웃을 그대로 두고 잘라낸 상대 발판만 쓴다.

## 원본 근거 (pokerogue `13f1139`, assets `009cac3`)

- 배경 `_bg` 는 320×180 이고 아래 48줄은 메시지 창이 덮는다. 보이는 필드는 320×132 다.
- `ArenaBase` 는 `_a`(아군)·`_b`(상대)를 320×132 레이어로 그린다. 등장 연출 뒤 아군 x 0, 상대 x 20.
- 발 위치는 아군 (106,148), 상대 (236,84). 더블은 LEFT (−32,−8), RIGHT (+32,0).
- 스프라이트는 배율 1, 원점 (0.5, 1)이다. 기술 연출은 발에서 32칸 위를 초점으로 쓴다.
- `end` 발판만 프레임 아틀라스이고 12fps 로 반복된다.

## 왜 이렇게 구현했나

**좌표는 `BattleFieldScene` 한 곳에 둔다.** 필드 크기만 받아 배율·원점·발 위치·발판 사각형을 계산하는
값 타입이다. 전장 뷰, 아레나 그리기, 테스트가 같은 계산을 쓰므로 어긋날 수 없다.

**배율은 전장 높이에서 나온다.** `BattleSpriteSizing.pixelScale` = 전장 높이/132 이고, 장면 배율도
같은 식이다. 효과 플레이어(`battle-player.js`)는 `field.setScale(scale)` 로 원본 애니메이션 필드 전체를
키우므로, 같은 값을 넘기면 기술 연출도 포켓몬과 같은 비율이 된다.

**무대 상자는 원본 초점 상자다.** 무대(64칸 정사각 + 발 여백)의 바닥이 발, 중심이 발 위 32칸이다.
효과 코드는 무대의 `midX`·`maxY − footInset`(발)과 `midY`(초점)를 쓰므로 원본 초점과 맞는다.
큰 포켓몬은 상자 밖으로 넘치지만 잘리지 않는다. 전장 전체가 `clipShape` 로 잘린다.

**HP 카드는 열을 나눠 모서리에 붙인다.** 처음엔 상대·아군 카드를 세로 한 줄로 쌓았는데, 더블에서
네 장의 높이 합이 전장(299pt)을 넘어 전장이 늘어나고 발 위치가 밀렸다(통합 테스트가 잡음).
상대는 왼쪽 위, 아군은 오른쪽 아래로 서로 다른 열이라 각자 모서리에 붙이면 겹치지 않는다.

**넓은 창에서는 배경만 넓힌다.** 필드가 장면보다 넓으면 배경을 가로에 맞춰 키운다. 발판·발은 높이 배율을
유지해 포켓몬과 어긋나지 않는다. 기본 창 크기에서는 배경도 같은 배율이다.

**`end` 아틀라스는 sRGB 로 합성한다.** 처음엔 DeviceRGB 컨텍스트에 프레임을 그렸는데, 화면에서 원본 PNG
보다 색이 달라졌다(아레나 렌더 테스트가 잡음). 원본 PNG 색공간인 sRGB 로 고쳤다.

**`end` 발판은 파일명 순서로 재생한다.** 원본 `arena-base.ts` 는 `generateFrameNames(start: 1, zeroPad: 4)` 로
0001→0016 을 재생한다. JSON 은 패킹 순서(0001,0002,0003,0004,0015,…)라 배열 순서로 돌리면 매 주기 튄다(리뷰 지적).

**SCREEN 초점 효과는 배경과 같은 규칙으로 놓는다.** 효과 플레이어는 원본 화면(320×180) 좌표를 전장 크기로
늘렸는데, 배틀러가 원본 좌표에 서면서 적을 겨눈 그래픽이 45pt 이상 어긋났다. `screenFocus` 는 장면이 더 넓은
기본 상태에서 크롭 원점만큼 옮기기만 하고, 전장이 더 넓을 때만 배경처럼 균일하게 키운다. 날씨가 양끝까지
닿아야 한다는 기존 테스트도 그대로 통과한다.

**사파리는 기존 크기를 유지한다.** 키 기반 크기 함수는 `physicalSize` 로 이름을 바꿔 사파리 전용으로
남겼다. 사파리 스프라이트는 종별 배율(`physicalSize / 아틀라스`)을 넘겨 이전과 같은 크기로 그린다.

## 에셋

`scripts/prepare-pokerogue-arenas.py` 가 고정 리비전에서 `_a`·`_b`(+있으면 `.json`)까지 받고
`manifest.json` 에 해시를 기록한다. 쓰기 전에 전부 검증해 일부만 바뀌는 일이 없다. 고지는 `PokeRoguePlayer/NOTICE.md`.

## 검증

- `BattleFieldSceneTests`: 배율·원점·발 좌표(싱글·더블)·발판 위치·무대 초점·넓은 창 배경.
  상대 발판 오프셋(20)을 0 으로 바꾸면 실패하는 것을 확인했다.
- `BattleArenaTests`: 16개 아레나 렌더에서 양쪽 발판의 왼쪽 윤곽 픽셀이 원본 색이다. 상대 발판을 아군 자리에
  그리게 바꾸면 16건 실패한다. 사파리용 잘린 발판도 검증한다.
- `BattleSharedGroundTests`: 실제 `BattleView` 더블에서 네 무대가 원본 발 좌표에 있다(기절 프레임 포함).
- 크기 테스트는 "작은 무대 안에 들어간다"는 이전 규칙 대신 "아틀라스 × 배율"을 확인한다. 리자몽/뮤 같은
  비율 기준은 원본 아틀라스 값(리자몽 83, 뮤 60 등)으로 낮췄다.
- `BattleFieldScreenFocusTests`: `end` 프레임이 0001~0016 순서인지, SCREEN (236,84) 가 적 발 위치에 놓이는지
  (넓은 창에서는 배경 배율) 확인한다. 정렬을 빼거나 예전 늘이기 매핑으로 되돌리면 각각 실패한다.

## 남은 한계

- 더블에서 아군 HP 카드 두 장(약 112pt)이 상대 오른쪽 포켓몬의 발판 아래쪽과 발을 일부 가린다.
  카드가 원본 정보창보다 커서 생긴다. 카드를 줄이거나 배치를 바꾸는 것은 별도 결정이 필요하다.
- `battlers` 측정은 이제 카드 영역이라 "전장 안에 있다" 단언은 항상 참이다. 스프라이트가 원본처럼 전장 밖으로
  넘치는 것은 의도이고, 위치는 `stages` 측정으로 따로 검증한다.
