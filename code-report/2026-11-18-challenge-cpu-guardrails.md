# 싱글 챌린지 CPU의 의미 없는 기술 선택 수정 (2026-11-18)

## 증상과 범위

슬리퍼가 첫 턴부터 방어, 골덕이 명상을 연속 사용. 트레이너 27명 × 플레이어 팀 3개 × 3가지 진행
(CPU 기술 선택 5,202번, 25턴)을 전수 집계하니 같은 부류가 490번 나왔다: 장판·벽 반복 167, +2 이상 강화 75,
방어 연속 62, 최대 랭크 강화 53, 상태이상 중복 34, 같은 날씨 31, 이유 없는 방어 23, 대타 중 대타 23,
만피 회복 22. 더블(손으로 짠 별도 정책)은 626번 중 방어 연속 5번뿐이라 대상에서 뺐다.

## 근본 원인

싱글 CPU는 사람 대전 기록을 흉내 내도록 학습한 선형 점수 모델이다.
1. 데이터상 위력이 0인 공격기(지구던지기·나이트헤드·은혜갚기·풀묶기·로킥·자이로볼·기사회생·잠재파워)는
   공격 점수가 0이 되고, 보조 기술 일괄 가산점(+0.247)에 진다. 슬리퍼 방어의 직접 원인.
2. "현재 랭크·상대 상태이상" 같은 상태 특징이 모든 후보에 같은 값으로 들어가 선택을 가르지 못한다.
   그래서 강화가 한 번 이기면 +6이 돼도 계속 이긴다.
3. 테스트는 모방 정확도와 롤아웃 승률만 봤고, "선택한 기술이 지금 효과가 있는가"를 보지 않았다.

## 결정: 재학습 대신 규칙 보강 (사용자 선택)

학습 가중치는 그대로 두고 앞단에 규칙(`challenge-cpu-rules.cjs`)을 둔다.
- **실패 확정 기술 제외:** 최대 랭크·만피 회복·대타 중복·상태이상/면역 상대·같은 날씨·최대 장판·중복 벽.
- **판단 규칙(사용자 요청):** 방어는 연속 금지, 바라기 대기나 상대 독·화상·씨뿌리기가 있을 때만. 강화는 +2까지.
- **실제 위력 반영:** 위력 0 공격기를 공개 정보(레벨·몸무게·스피드·체력)로 환산.
- 교체는 절대 제거하지 않고, 기술이 전부 무의미하면 원래 목록을 유지한다(억지 교체 방지).
- 상대의 공개 효과(대타·씨뿌리기·혼란·하품)와 내 직전 기술·바라기는 화면 정보에 없어 `runCPU` 가 넘긴다.
  상대의 숨은 정보(개체값·도구·특성)는 쓰지 않는다.

## 왜 정책 버전을 나눴나

진행 중인 챌린지는 저장된 플레이어 입력을 같은 시드로 **재생**해 이어진다. 같은 버전에서 CPU 판단만
바꾸면 재생이 어긋나 저장 판이 깨진다. 그래서 출시된 모델을 바이트 그대로 `challenge-policy-v2.json` 으로
보존해 옛 버전 값(`02bc7a49…`)을 유지하고, 새 `challenge-policy.json` 은 `"cpuRules"` 한 줄만 더해 새 버전을
만든다. 앱은 v2 를 지원 버전으로 인정하고, `build-app.sh` 는 두 새 파일을 번들에 넣는다.

## 검증

- 엔진 테스트 10개(버전 보존, 슬리퍼 첫 턴, 규칙별, 전부 무의미할 때, 위력 환산, CPU 상황 전달,
  트레이너 7명 실전 집계). 핵심 지점 7곳에 결함을 주입해 모두 실패 확인 — 처음엔 3곳을 놓쳐
  (위력 환산이 결과를 가르지 않는 장면, 상황 정보 경로 미사용) 테스트를 보강했다.
- Swift: 보존 버전(v2) 저장 판이 같은 결정·HP·PP 로 재생되는지. v2 지원을 빼면 실패함을 확인.
- 같은 전수 집계: 490 → 1 (PP 소진 후 전부 무의미해진 예외 추정, PP 상태는 미확인).

## 남은 것

- 더블의 방어 연속 5건은 그대로다(별도 정책·버전).
