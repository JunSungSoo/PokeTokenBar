# 설정 화면 Release Note 버튼 (2026-11-20)

## 결정

- 설정 화면 맨 아래("정보 & 지원" 마지막 행)에 **Release Note** 버튼을 둔다. 누르면 별도 창이 열린다.
- 내용은 친구 배포용으로 써 온 한국어 배포 이력 `docs/releases/zip/00-Release History.txt` 다(사용자 선택).
- 버튼 이름은 사용자가 지정한 "Release Note" 를 모든 언어에서 그대로 쓴다. 옆 설명만 다국어다.

## 왜 이렇게 구현했나

**별도 창.** 설정은 메뉴바 팝오버 안에 있어 시트를 쓰지 않는다(`PopoverView` 의 화면 전환 규칙).
팝오버가 닫혀도 노트가 남도록 `RedMapleWindow` 와 같은 독립 창 패턴을 썼다.

**원본은 docs, 앱에는 사본.** SwiftPM 리소스는 타깃 폴더 밖 파일을 참조할 수 없다. 패키징 규칙이
`docs/releases/zip/` 경로를 고정하므로 원본을 옮기지 않고 `Resources/ReleaseNotes/` 에 사본을 둔다.
두 파일이 다르면 `ReleaseHistoryTests` 가 실패한다(일부러 한 줄 덧붙여 실패를 확인했다).
`build-app.sh` 는 다른 리소스 폴더처럼 서명된 리소스 번들로 옮기고, QA 앱 스크립트 두 곳도 함께 복사한다.

**파서는 형식에 엄격하게.** 제목은 `YYYY-MM-DD (N차 배포)` 만 인정하고, `- ` 가 아닌 줄은 앞 변경사항에
이어 붙인다. CRLF 도 나눈다(리뷰 지적).

## 검증

- 앱 사본 = 문서, 날짜별 항목·순서·변경 수, CRLF·줄바꿈 이어붙이기, 창 열기·재사용, 실제 창에 글자가 그려짐.
- 버튼 위치는 테스트로 확인할 수 없었다. 이 화면의 SwiftUI 버튼은 `NSButton` 이 아니고, 테스트 프로세스에는
  접근성 클라이언트가 없어 접근성 트리도 만들어지지 않는다. 렌더 이미지(`assets/settings-release-note.png`)로
  맨 아래 행임을 확인했다. 단언 없는 렌더 테스트는 아무것도 지키지 못해 넣지 않았다.
