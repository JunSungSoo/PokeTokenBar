# 아르세우스 배틀 참가 규칙 변경 (2026-11-18)

## 결정

- 아르세우스(#493)는 **수집한 폼의 타입 그대로** 배틀에 참가한다. 플레이트는 쓰지 않고 지닌 물건 칸은 자유다.
- 심판의뭉치는 폼 타입을 따른다.
- 아르세우스만 멀티타입 대신 **프레셔(슬롯 1) / 적응력(슬롯 2)** 중 하나를 고른다.
- 기존에 멀티타입으로 저장된 개체는 프레셔가 된다. 적응력은 사용자가 직접 골라야 한다.

## 왜 이렇게 구현했나

**규칙의 원천을 엔진 오버레이 한 곳에 둔다.** `BattleEngine/held-items.cjs` 의 `battleDex()` 가 이미
메가·페어리 기술을 얹는 자리라, 아르세우스도 같은 곳에서 덮어쓴다.

- 도감 항목(493 전 폼): 특성을 프레셔/적응력으로, `requiredItems` 제거, 페어리 폼은 5세대로 취급.
- `arceus` 종 조건: 원본은 8세대 미만에서 멀티타입이 아니면 타입을 노말로 되돌린다. 폼 타입을
  쓰려면 이 조건을 비워야 한다. (처음엔 도감만 덮어썼다가 노말 외 폼이 전부 노말로 나와 발견.)
- 심판의뭉치: 원본 콜백을 먼저 부르고, 플레이트가 없는 아르세우스면 폼 타입으로 바꾼다.

**앱은 엔진에서 뽑은 데이터를 쓴다.** 특성 선택지는 `scripts/export-battle-abilities.cjs` 가 생성하는
`ability-options.json` 이 원천이다. Swift 에 아르세우스 전용 특성 목록을 따로 적지 않았다.

**저장 데이터 이전은 기존 장치를 재사용한다.** `PokemonProfile.enrich` 의 "과거 특성 보정"이
PokéAPI 특성(멀티타입)이 선택지에 없으면 같은 슬롯의 특성으로 바꾼다. 슬롯 1 = 프레셔라
별도 이전 코드 없이 처리된다. 종 캐시(PokéAPI 원본)는 건드리지 않는다.

**자격 함수는 통째로 제거했다.** `isSpeciesEligible` 은 493만 걸러내던 함수라 규칙이 사라지면
항상 참이다. 호출부 8곳과 안내 문구 `battleItemTypeExcluded` 를 함께 지웠다.

## 작업 중 발견한 문제

- **더블 챌린지 편성 모델**(`challenge-doubles-lineup.cjs`)이 플레이어 로스터의 종을 기본 5세대
  도감에서 찾고 6세대면 오류를 냈다. 페어리 아르세우스가 여기서 막혔다. 오버레이 도감을 보도록 수정.
- 엔진 `REVISION` 은 바꾸지 않았다. 바꾸면 저장된 챌린지 체크포인트가 무효가 된다. 대신 이전
  버전 앱과 P2P 대전 시 상대 엔진은 아르세우스 팀을 오류로 거부한다.

- **배틀 로그 이름**(코드 리뷰에서 발견): 생성 파일 `catalog.json` 의 별칭에 페어리 폼만 없어
  "알 수 없는 포켓몬"으로 표시됐다. 생성 원본(PokeAPI CSV)을 다시 돌릴 수 없어, 재생성에도
  유지되도록 `BattleTextCatalog` 조립 단계에서 별칭을 합친다.

## 남은 사항 (미수정)

- **구버전 상대와의 P2P 로비**: 신버전이 아르세우스 팀을 보내면 구버전은 오류만 띄우고, 신버전
  쪽은 원인 표시 없이 대기 상태가 된다. 로비를 취소하면 빠져나온다. 해결하려면 체크포인트와
  분리된 P2P 프로토콜 버전이 필요하다.
- **심판의뭉치 연출 타입**: 엔진의 연출 이벤트는 기술의 고정 타입(노말)을 내보낸다. 숨은 힘 타입
  비공개를 위한 기존 설계라 그대로 뒀다. 메뉴·상성·데미지는 폼 타입이다.

## 검증

- 엔진: 18타입 × 2특성 × 싱글/더블에서 타입·특성·폼·지닌 물건 확인, 심판의뭉치 타입(메뉴 표시와
  시뮬레이터 이벤트 양쪽), 비아르세우스의 심판의뭉치는 노말 유지, 멀티타입 거부, 더블 챌린지 편성.
- Swift: 멀티타입 저장 개체가 팀 구성 시 프레셔로, 적응력 선택 개체는 적응력으로 엔진에 전달되는지,
  상세 페이지 로드 시 저장 프로필이 프레셔로 이전되고 적응력 선택이 유지되는지.
