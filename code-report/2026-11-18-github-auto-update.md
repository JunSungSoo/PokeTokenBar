# GitHub Releases 앱 내 자동 업데이트 (2026-11-18)

## 목표와 결정

"그래도 열기" 확인 없이 업데이트를 설치한다. 유료 공증은 쓰지 않는다. 사용자 결정:
JunSungSoo 포크 Releases / 버튼 한 번으로 설치 / 확인은 GitHub 로 전환(Drive ZIP 은 최초 설치용) /
서명 키는 로그인 키체인.

## 왜 이 구조인가

**격리 표시를 피하는 것이 유일한 무료 경로다.** Gatekeeper 는 격리 표시가 있는 파일만 검사하고, 앱이
`URLSession` 으로 받은 파일에는 표시가 붙지 않는다. 구현 전에 macOS 26.5 에서 시험 앱으로 실측했다
(자기 교체·다른 앱 교체·로그인 항목 유지 모두 권한 요청 없음). 설계는 이 실측에 기대고 있다.

**Gatekeeper 가 빠진 자리를 서명된 매니페스트가 채운다.** ad-hoc 코드 서명은 누구나 만들 수 있어
출처를 증명하지 못한다. 그래서 Ed25519 로 서명한 매니페스트(버전·자산명·크기·SHA-256)를 앱에 내장한
공개 키로 검증한다. Sparkle 의 EdDSA 방식과 같은 원리이고 CryptoKit 만으로 된다(의존성 추가 없음).
- 다운로드 주소는 네트워크에서 읽지 않고 서명된 버전으로 만든다 → 주소 조작 여지를 없앤다.
- 현재보다 높은 버전만 설치 → 옛 서명 매니페스트를 재사용한 다운그레이드를 막는다.
- `releases/latest/download/` 고정 주소를 써서 GitHub API 호출 제한(시간당 60회)을 피한다.

**교체 코드는 기존 설치 프로그램 것을 공유한다.** `BundleInstallation` 을 `scripts/zip-installer` 에서
`Core/Update` 로 옮겨 앱과 Drive ZIP 설치 프로그램이 같은 파일을 컴파일한다. 같은 폴더에 복사(서명 재검증)
→ `renameatx_np` 맞바꾸기 → 옛 번들 삭제. 디렉터리 잠금과 "설치된 버전이 그사이 바뀌지 않았는가" 확인 포함.

**재실행은 새 인스턴스가 기다리게 했다.** `SingleInstance` 는 같은 경로에서 먼저 뜬 인스턴스가 있으면
새 쪽이 물러난다. 그래서 새 번들을 `--ptb-wait-for-pid` 인자로 띄우고, 새 인스턴스가 이전 프로세스 종료를
확인한 뒤 시작을 이어간다. 자식 프로세스로 재실행 스크립트를 띄우는 방식은 로그인 항목(launchd)으로
실행된 경우 앱 종료 때 함께 정리될 수 있어 쓰지 않았다. LaunchServices 로 띄운 인스턴스는 독립적이다.

**배틀·챌린지·교환 중에는 설치하지 않는다.** 종료가 진행 중인 판을 끝내기 때문이다. 종료 확인 창을
띄우는 대신 아예 시작하지 않고 안내한다.

## 검증

- 테스트 31개(서명·변조·필드 검증, 해시·크기, 압축 해제·번들 검증, 교체·버전 변경 거부, 이동 위치,
  재실행 인자, 확인기 상태). 핵심 가드 9곳에 결함을 주입해 모두 실패함을 확인했다(1곳은 처음에 놓쳐
  테스트를 고침: 존재하지 않는 경로라 다른 검사로 먼저 실패하던 문제).
- `PTB_DRY_RUN=1` 로 실제 universal 배포물을 만들고, 앱 코드가 내장 공개 키로 그대로 받아들이는지
  확인했다(`PTB_UPDATE_ARTIFACTS`).

## 코드 리뷰 반영 (Critical 0, Important 3 모두 수정)

- 차단 조건을 다운로드 전에만 봐서, 받는 동안 시작한 배틀이 종료 확인 창과 30초 대기 초과로 앱이 하나도
  안 남는 경로가 있었다 → 교체 직전에 다시 확인한다.
- 교체 후 재실행 실패를 "설치 실패"로 안내하고 재시도는 버전 불일치로 실패했다 → "다시 시작 필요"로 구분하고 재시도를 막는다.
- 종료 경로가 `defer` 를 건너뛰어 업데이트마다 내려받은 파일이 남았다 → 종료 전 삭제 + 시작 시 정리.
- Minor 반영: 배포 스크립트가 미추적 파일을 못 보던 게이트, 다음 확인 때 "배틀 중" 안내 해제, 여러 줄 주석.
- Minor 미반영(문서에 기록): 매니페스트 만료 없음, 서명 키의 `security` 무확인 접근.
- 새 가드 3곳도 결함 주입으로 테스트가 잡는 것을 확인했다(누계 12곳).

## 남은 것

- 재실행 인계(실제 앱 종료 → 새 버전 시작)는 실제 앱으로 돌려보지 않았다. 사용자의 실제 세이브와
  로그인 항목을 건드리기 때문이다. 첫 실제 릴리스에서 확인한다.
- 3.2.1 이하 설치본은 Drive 만 확인하므로, 이 기능이 든 첫 버전은 Drive 로 한 번 더 배포해야 한다.
